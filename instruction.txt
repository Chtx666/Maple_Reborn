Maple 是 Godot 4.6 开发的 Galgame（视觉小说），核心的系统主要由剧本渲染引擎（处理文本、立绘、背景和分支）和状态管理器（处理存档、读档和变量追踪）组成。以下约定与 project.godot 及 Scripts/ 下的现有代码同步，与项目实际不符的通用教程内容已剔除。

为了高效地记录和管理这些数据，业界通常会将其分为静态剧本数据（游戏资源怎么跑）和动态运行时数据（玩家当前玩到哪）两部分。以下是具体的实现方案：

一、 静态剧本数据（台词、人物、背景、选项）
不要把剧本和逻辑硬编码在 GDScript 里，应该使用结构化文本。常见的做法有两种：自定义 DSL 或通用结构化格式（如 JSON / YAML）。

本项目已选定 JSON，不再考虑 YAML：它极易被解析，且能完美表达树状的分支结构。

1. 数据结构设计示例（对应当前 test_script.json）
顶层是章节表，章节内部再挂节点表。章节之间用 next_chapter 串成链，章节结束用保留节点 ID "chapter_end" 作哨兵。

JSON
{
  "title": "Maple",
  "start_chapter": "1",
  "end_chapter": "7",
  "end_node": "2-6",
  "chapters": {
    "1": {
      "start_node": "1-1",
      "next_chapter": "2",
      "nodes": {
        "1-1": {
          "type": "dialogue",
          "bg": "menu_bg",
          "character": "fuu_1",
          "speaker": "???",
          "text": "……啊，你好。你也是来散步的吗？",
          "next": "1-2"
        },
        "1-2": {
          "type": "choice",
          "speaker": "枫",
          "text": "（她把目光移向坡道尽头，等你回答。）",
          "options": [
            { "text": "陪她一起走", "next": "1-3" },
            { "text": "先站在原地", "next": "1-4" }
          ]
        },
        "1-3": {
          "type": "dialogue",
          "bg": "menu_bg",
          "character": "fuu_1",
          "speaker": "枫",
          "text": "那就走吧。",
          "next": "chapter_end"
        },
        "1-4": {
          "type": "dialogue",
          "bg": "menu_bg",
          "speaker": "...",
          "text": "她愣了一下，随即笑了笑，自己先迈出了步子。",
          "next": "chapter_end"
        }
      }
    }
  }
}
2. 各要素如何记录：
台词 (text) & 说话人 (speaker)：显式记录。项目暂无多语言需求，text 直接存正文；将来若要本地化，再改为文本 ID + 语言包索引。

当前人物图 (character) & 背景图 (bg)：只记录资源的 Key，不带扩展名。GameProcess.gd 读到字符串后拼成 res://Assets/Pictures/<key>.png 加载并渲染。立绘消失传 null，代码会把 texture 置空。

对话选项 (options)：

text: 选项显示的文字。

next: 点击该选项后，剧情跳转的下一个节点 ID。沿用节点统一的 next 字段，不另造 target_node。

set_variable: 核心机制，当前尚未实现。选择该选项后触发的变量修改（如好感度递增、标记该选项已被选）。

二、 动态运行时数据（选择过的选项、当前状态）
这部分数据存在于游戏运行时的内存中。为了实现“选择过的选项”以及“根据之前的选择改变剧情”，你需要引入一个全局变量池（Variable Pool / Blackboard）。

1. 记录“选择过的选项”
不需要记录大段的文字，只需要记录标签（Flag）。

方法 A（布尔标记法，推荐）：在选项触发时，在变量池中存入一个布尔值。例如 flags["choice_lead_way"] = true。下次遇到需要判断的地方，检查这个 Flag 即可。

方法 B（已选列表法）：建立一个全局数组 chosen_options: Array[String]，当玩家点击某个选项时，将该选项的唯一 ID（如 ch1_opt_1）塞进数组里。选项标绿（表示已选）或剧情判定时，用 has() 检查该 ID 是否在数组中。

三、 存档与读取功能 (Save / Load)
Galgame 的存档本质上就是把当前运行时的内存状态序列化（Serialized）为本地文件（如文本或二进制）。本项目使用 JSON 文本，便于直接查看和手改。

一个标准的 Galgame 存档需要包含以下三部分数据：

1. 存档文件的数据结构 (Save File Data)
每个档应该是一个独立的 JSON 或二进制文件，结构如下：

JSON
{
  "meta_data": {
    "save_time": "2026-05-16 23:15:00",
    "preview_text": "那个……请问你知道学生会办公室...",
    "chapter_label": "第一章：枫坂"
  },
  "engine_state": {
    "current_chapter": "1",
    "current_node": "1-2",
    "current_bg": "menu_bg",
    "current_characters": {
      "center": "fuu_1"
    }
  },
  "game_variables": {
    "heroine_favor": 1,
    "flags": {
      "choice_lead_way": true,
      "met_heroine": true
    },
    "has_read_nodes": ["1-1", "1-2"]
  }
}
meta_data（元数据）：用于在“选择存档”界面展示信息（如时间、章节名、缩略图路径、最后一句话）。不需要读入游戏，仅供 UI 显示。当前项目的存档文件名本身就是 unix 时间戳，时间可以不加进 meta_data，只在 UI 里用 Time.get_date_string_from_unix_time() 转换展示。

engine_state（引擎状态）：恢复现场用。最核心的是 current_chapter 和 current_node。有了这两个 ID，读档时引擎就能重新加载剧本，并直接跳转到对应的对话。为了防止读档瞬间画面闪烁，通常也会把当时的背景和立绘记下来直接渲染。

game_variables（游戏变量）：恢复玩家的记忆和数值（好感度、各种 Flag 状态）。

has_read_nodes（已读文本记录）：用于实现“快进时遇到未读文本自动停止”（Skip Read）的功能。只要把玩家经历过的所有节点 ID 塞进一个全局数组（存于系统存档或全局存档中），快进时判断当前 Node ID 是否在数组中即可。

2. 系统全局存档 (Global/System Save)
除了玩家主动存的单个档，Galgame 还需要一个全局存档（global.dat），它不随单次游戏重新开始而重置：

记录画廊（CG 收集情况）。

记录音乐鉴赏（BGM 解锁）。

记录全结局触发状态（用于解锁真结局/True End）。

记录所有周目里所有已读过的文本 ID（用于跨周目的已读快进和文本变色）。

四、 开发实现建议（Godot 4.6 / GDScript）
项目已自研引擎，不引入 Dialogic 等插件，下列约定与现有代码保持一致。

节点管理不用基类继承，改用 Dictionary + type 字段分发：node_iteration() 读出节点后按 type 值分别调用 node_process()（dialogue）或 choice_process()（choice）。新增节点类型只需加一个分支，不必新建类。

章节与节点的推进是两层迭代：chapter_iteration() 取章节、处理 next_chapter 换章；node_iteration() 分发单节点、识别 chapter_end 哨兵。

读档的执行流程：

玩家点击读档 -> 读取 user://saves/<时间戳>.save。

解析出 engine_state，加载 current_bg 和 current_characters。

将 game_variables 覆盖到当前游戏的全局变量池中。

加载 current_chapter，把当前节点指针指向 current_node。

刷新UI，游戏继续。

存档现状：目前只写入 { current_chapter, current_node } 两个字段，engine_state 与 game_variables 尚未接入。
